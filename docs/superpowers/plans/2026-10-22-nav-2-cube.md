# Navigation on the cube Implementation Plan (2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cube bonds an iPhone next to the Mac, both connected at once, and while the phone sends navigation frames it shows a heading-up map (route, streets, rider, turn banner, Vietnamese street names) that takes over the screen until the ride ends.

**Architecture:** The phone does all geometry; the cube receives ready-to-draw frames on a new Nav characteristic, reassembles and decodes them in pure, host-tested code (`nav_frame.h`), tracks the ride's lifetime in a pure `NavSession`, and draws with a new `uiNav` screen in `ui.cpp`. Bonding moves from "one Mac" to "one Mac + one iPhone" in a pure policy (`ble_bonds.h`) applied by `net_ble.cpp`.

**Tech Stack:** C++ (gnu++11 on the board, C++17 in host tests), NimBLE-Arduino, LovyanGFX, the existing `firmware/sim` (SDL simulator, `make test`, `make shot`, `make bench`), Python + Pillow for `tools/gen_fonts.py`.

**Spec:** `docs/superpowers/specs/2026-10-22-moto-navigation-design.md`

## Global Constraints

- Screen 240×280, rider arrow drawn by the cube at (120, 200) pointing up.
- Strings on the wire are UTF-8 NFC; the firmware never formats numbers for navigation (the phone sends `"150 m"`, `"12 min"`).

- Power target from the spec: at least 8 hours of navigation on the 4000 mAh cell.

## Nav wire format (also consumed by plan 3)

Chunks: each write is `[ver=1][seq][idx][total]` + body bytes, same rules as Payload (`docs/ble-protocol.md`) except `total ≤ 32` and the reassembled frame `≤ 8192` bytes. A new `seq` replaces a half-finished frame (latest wins).

Reassembled frame, little-endian:

| Field | Type | Notes |
|---|---|---|
| version | u8 | `1` |
| state | u8 | `NavState`: 0 Ended, 1 Navigating, 2 Rerouting, 3 OffRouteNoSignal, 4 Arrived |
| turn | u8 | `NavTurn`: 0 Straight, 1 SlightLeft, 2 Left, 3 SharpLeft, 4 SlightRight, 5 Right, 6 SharpRight, 7 UTurn, 8 KeepLeft, 9 KeepRight, 10 Roundabout, 11 Arrive, 12 Rejoin |
| exit | u8 | roundabout exit number, 0 = none |
| dir | u8 | Rejoin arrow, 0..255 = 0..360° clockwise from screen-up (only meaningful for Rejoin) |
| flags | u8 | bit0 = GPS weak (rider arrow drawn grey) |
| dist | u8 len + UTF-8 | ≤ 15 bytes, e.g. `150 m` |
| street | u8 len + UTF-8 | ≤ 63 bytes |
| eta | u8 len + UTF-8 | ≤ 23 bytes, e.g. `12 min` |
| nRoute | u16 | ≤ 256, then nRoute × (i16 x, i16 y) screen px |
| nStreets | u8 | ≤ 96, then each: u8 cls (0–3, as the server's tiles), u8 nPts (≥ 2), nPts × (i16 x, i16 y); total street points ≤ 640 |

Coordinates are screen pixels of the 240×280 frame, already clipped by the phone to x ∈ [−64, 304], y ∈ [−64, 344]. Any length over its limit, a truncated body, or trailing bytes rejects the frame (the last good frame stays).

Golden frames (go in `firmware/sim/fixtures/nav-frames.txt`, one per line, `nav <name> <hex>`):

```
# turn: Navigating, Right, "150 m", "Lê Lợi", "12 min", route (120,200)(120,90)(200,80), one cls-2 street (0,150)(240,160)
nav turn 01 01 05 00 00 00 05 31 35 30 20 6d 09 4c c3 aa 20 4c e1 bb a3 69 06 31 32 20 6d 69 6e 03 00 78 00 c8 00 78 00 5a 00 c8 00 50 00 01 02 02 00 00 96 00 f0 00 a0 00
# arrived: Arrived, Arrive, "", "Bến Thành", "", no route, no streets
nav arrived 01 04 0b 00 00 00 00 0c 42 e1 ba bf 6e 20 54 68 c3 a0 6e 68 00 00 00 00
# offroute: OffRouteNoSignal, Rejoin, dir 64 (90° right), GPS weak, "80 m", route (-64,304)(300,-64)
nav offroute 01 03 0c 00 40 01 04 38 30 20 6d 00 00 02 00 c0 ff 30 01 2c 01 c0 ff 00
```

## Review Focus

1. The phone's link drops mid-ride (pocket, interference) — the cube keeps the last frame, shows `NO PHONE` after 3 s, returns to the deck after 20 s, and resumes the map when frames come back; `nav_session_test`.
2. A street name too long for 240 px (`Đường Nguyễn Văn Linh nối dài`) — truncated with `...` at a character (not byte) boundary, never splitting a UTF-8 sequence; `@nav-long` shot plus a unit test of the UTF-8-aware truncation helper.
3. The Mac reconnecting while navigation runs (or the Mac pushing settings/volume) — the map stays up, the Mac's payload still updates the deck underneath, and the Volume card/unlock prompt never cover the map; integration check in Task 6 via `CUBE_BLE=live CUBE_NAV=turn make run`.
4. A third device pairing while the pairing window is closed — refused and its bond deleted, both existing bonds intact; `ble_bonds_test`.
5. Coordinates at the clip limits or a frame with zero route points — draws without overflow or crash; decoder and `@nav-arrived` / `offroute` shots cover them.

- Boot with `blePairingOpen()`: show `uiMessage(lcd, "PAIRING OPEN", "PAIR FROM THE APP OR MAC")` until the window ends or a passkey appears.
