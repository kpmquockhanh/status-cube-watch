# Navigation server Implementation Plan (1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `https://nav.devxdev.site` answers motorbike routes for Vietnam and serves street tiles, behind a secret key, rebuilt monthly, on the `contabo` VPS.

**Architecture:** GraphHopper 11.1 (official jar on Eclipse Temurin 21) builds a graph from the Geofabrik Vietnam extract with a Vietnam motorbike custom model. A zero-dependency Node script turns the same extract (exported by `osmium`) into static street tiles at zoom 15. The existing n8n nginx container gets a second site that checks the key, proxies `/route` to GraphHopper and serves tiles as static files.

**Tech Stack:** Docker Compose, GraphHopper 11.1, osmium-tool, Node ≥ 20 (ESM, no npm deps, `node --test`), nginx 1.27 (existing), certbot (existing), bash.

**Spec:** `docs/superpowers/specs/2026-10-22-moto-navigation-design.md`

## Global Constraints

- Host: `ssh contabo` (root, Debian 13, x86_64, 4 cores, 7.8 GB RAM + 4 GB swap, Docker 29). n8n lives in `/root/n8n` (compose `docker-compose.prod.yml`, services `postgres n8n nginx certbot`, network `n8n_default`) and must keep working after every step.
- Public name `nav.devxdev.site` (already resolves through Cloudflare, like `n8n.devxdev.site`).
- Every request needs header `X-Nav-Key: <key>`; anything else gets `401`. The key is never committed.
- Runtime data lives on the host under `/root/nav/` (not in git). Repo files live in `nav-server/`.
- Routing profile name: `moto_vn`. Motorbikes are banned on Vietnamese expressways: `road_class == MOTORWAY` must never appear in a route.
- Extract: `https://download.geofabrik.de/asia/vietnam-latest.osm.pbf`.

## API contract (consumed by plan 3)

- `POST /route` — body is GraphHopper's JSON route request; the app always sends `{"points":[[lon,lat],[lon,lat]],"profile":"moto_vn","instructions":true,"points_encoded":false,"locale":"en","details":["road_class"]}`. Response is GraphHopper's unchanged.
- `GET /tiles/15/{x}/{y}.json` — street tile (slippy-map XYZ numbering, zoom 15). `404` means no streets there (treat as empty). Body:
  `{"v":1,"z":15,"x":X,"y":Y,"w":[[cls, lat0, lon0, lat1, lon1, ...], ...]}` — `cls` 0 = motorway/trunk (+ `_link`), 1 = primary/secondary (+ `_link`), 2 = tertiary (+ `_link`)/residential/unclassified/living_street, 3 = service. Coordinates are integers, degrees × 1e6. Each entry is one run of a way that touches the tile (it may extend one point beyond the tile so lines meet across edges). Other `highway` values are not included.
- `GET /health` — `200` when GraphHopper is up.

## Review Focus

1. A route between two Ho Chi Minh City points that a car would take over an expressway (e.g. via the HCMC–Long Thanh–Dau Giay expressway) — must avoid it; the smoke test asserts no `MOTORWAY` in `details.road_class`.
2. A request without the key, or with a wrong one, reaching GraphHopper or the tiles — must be `401`; smoke test covers both endpoints.
3. A monthly refresh that fails half-way (download cut, import OOM) — the live graph and tiles must stay untouched and serving; `refresh.sh` test with a deliberately bad URL.
4. nginx reload after adding the nav site breaking n8n — the deploy task checks `https://n8n.devxdev.site/` still answers (401 basic-auth is the healthy answer) after every nginx change.
5. A way crossing a tile edge — both tiles must contain it so the cube's map has no gaps at tile seams; unit test in Task 1.

### Task 1: Street tile builder

**Files:**
- Create: `nav-server/tiles/tiles.mjs` (pure functions)
- Create: `nav-server/tiles/build-tiles.mjs` (CLI: reads osmium GeoJSONSeq on stdin, writes tiles)
- Test: `nav-server/tiles/tiles.test.mjs`

**Interfaces:**
- Produces: `lonLatToTile(lon, lat, z) -> {x, y}`; `tileBounds(x, y, z) -> {west, south, east, north}`; `roadClass(highway: string) -> 0|1|2|3|null`; `splitIntoTiles(coords: [lon,lat][], z) -> Map<"x/y", [lon,lat][][]>`; `encodeTile(x, y, z, entries: {cls, coords}[]) -> string`. CLI: `osmium export … -f geojsonseq | node build-tiles.mjs <outDir>` writes `<outDir>/15/<x>/<y>.json` and a gzip twin `<y>.json.gz`.

- [ ] **Step 1: Write the failing tests** (`node:test`, `node:assert/strict`):
  - `lonLatToTile(106.6980, 10.7725, 15)` equals `{x: 26095, y: 15397}` (Ben Thanh market; compute expected with the standard slippy formula in the test, and also assert these literal numbers).
  - `roadClass('trunk_link') === 0`, `roadClass('secondary') === 1`, `roadClass('living_street') === 2`, `roadClass('service') === 3`, `roadClass('footway') === null`.
  - Tile seam: a 2-point line from the centre of tile (26095,15397) to the centre of tile (26096,15397) appears in both keys `26095/15397` and `26096/15397`, each run containing both points.
  - A 5-point line wholly inside one tile yields exactly one run of 5 points in that tile.
  - `encodeTile` output parses to `{v:1,z:15,x,y,w:[[cls, lat*1e6 rounded, lon*1e6 rounded, …]]}` (latitude first).

- [ ] **Step 2: Run** `node --test nav-server/tiles/` — Expected: FAIL (module not found).

- [ ] **Step 3: Implement `tiles.mjs`.** Segment-to-tile assignment: for each segment take the tile range of its bounding box (at z 15 segments are short; bbox is enough), add the segment to each tile in that range, and join consecutive segments in the same tile into one run.

- [ ] **Step 4: Run** `node --test nav-server/tiles/` — Expected: PASS.

- [ ] **Step 5: Implement `build-tiles.mjs`.** Stream stdin line by line (`readline`); keep `LineString`/`MultiLineString` features whose `properties.highway` has a class; accumulate per-tile entries in a `Map`; when the map holds > 2,000,000 points, flush by appending to per-tile part files, and at the end merge parts per tile into the final JSON and gzip it (`zlib.gzipSync`). Print `tiles: N, ways: M` at the end.

- [ ] **Step 6: Check on a tiny extract.** Run on the Mac:

- Create: `nav-server/graphhopper/moto_vn.json`
- Create: `nav-server/refresh.sh`

**Interfaces:**
- Consumes: `build-tiles.mjs` from Task 1 (copied into the image at `/app/tiles/`).
- Produces: image `nav-graphhopper:11.1`; host dirs `/root/nav/data/graph` (live graph) and `/root/nav/data/tiles` (live tiles); `refresh.sh` usable from cron; GraphHopper listening on 8989 inside the container.

- [ ] **Step 2: Write `config.yml`**: `graph.encoded_values: car_access, track_type, road_access, road_class, car_average_speed, surface, max_speed, ferry_speed`; one profile `moto_vn` with `custom_model_files: [moto_vn.json]`; `profiles_ch` for `moto_vn` (speed mode, routes in ms); `graph.location` from `-Ddw.graphhopper.graph.location`; `import.osm.ignored_highways: footway,cycleway,path,pedestrian,steps,bridleway`; server `application_connectors` on `0.0.0.0:8989`, admin on `127.0.0.1:8990`.

- [ ] **Step 3: Write `refresh.sh`** (bash, `set -euo pipefail`, takes optional `PBF_URL`): download into `/root/nav/work/vietnam.osm.pbf`; import with `java -Xmx5g -jar graphhopper-web-11.1.jar import config.yml` into `/root/nav/work/graph`; build tiles into `/root/nav/work/tiles` (`osmium tags-filter … w/highway`, `osmium export -f geojsonseq`, `build-tiles.mjs`); only if all three succeed, `mv` live dirs to `*.old`, move work dirs live, `docker compose -f /root/nav-server/docker-compose.yml restart graphhopper`, wait for `/health`, then delete `*.old`.
